# Implementation provenance

This Rust crate was independently generated for the requested userspace API from STMicroelectronics specifications. It is MIT licensed; the initial Git commit is an orphan containing an MIT license. It does not inherit the GPL-2.0-only C driver's history or claim that its authors granted another license.

Contribution record: Guilhem defined and authorized this implementation's scope, isolated orphan history and MIT licensing choice. Codex generated the Rust implementation, examples, scripted tests and supporting documentation from the listed specifications and validated the local build. Guilhem/consumer maintainers own acceptance, the final Git dependency pin and physical qualification. Starting an orphan history does not change any rights or licensing obligations on the old driver or any other Git history.

Prior exposure: the researcher read the GPL-2.0-only CR14 kernel driver at upstream revision `f188d58` while inventorying observable capabilities and limitations. That exposure informed the requested capability list (inventory/anticollision, select/UID, block read/write, probe/cleanup) and the need to retain Linux busy-read errors. The old driver was not used as a port/translation source. No C expressions, source fragments or kernel implementation were copied or translated into this crate. Protocol constants, transaction layouts, tag states and timing values below come from the datasheets. This is **not a clean-room claim**: the same researcher had previously seen that source.

Independent implementation choices:

- The API owns a caller-provided `i2cdev` device, implements synchronous operations with `&mut self`, and uses that crate's existing traits for scripts. Linux error values are retained unchanged. Polling only reads treats `EREMOTEIO`/`ENXIO`/`ETIMEDOUT`/`EIO` as potentially busy until the operation's absolute deadline; this includes failure conditions the physical bus must distinguish.
- Parameter `10h` enables carrier with SOF/EOF answers and the 500 µs answer-start watchdog. I2C block writes carry only the CR14 RF length byte, with no additional SMBus Count byte. A separate two-message I2C_RDWR read reproduces the datasheet random-read sequence. Only well-formed replies are consumed.
- Initiate starts inventory. A CRC collision requests CR14's complete PCALL16 + fifteen SLOT_MARKER sequence. Masked slot IDs are copied before Select/Get_UID overwrite the shared frame. Resolved tags receive Completion; unresolved Select/UID CRC or lost-answer candidates receive Reset_to_inventory before a new round. Rounds continue while unresolved collisions exist, bounded by the deadline. UID comparison precedes any memory command.
- The library waits 20 ms before initial probing and 25 ms after RF enable (reader allowance plus 5 ms tag warmup). A successful RF answer imposes 200 µs before another request, greater than the 132 µs minimum. A verified RF-off register is followed by a conservative 20 ms off interval before reuse; the tag's power-off/reset depends on the actual RF field and must be qualified on the board.
- RF characters have ten 9.44 µs bits; requests include SOF/EOF and two hardware CRC bytes, plus inter-character spacing. The longest implemented request is six bytes and longest ordinary answer eight. Conservative library guards of 4 ms per ambiguous ordinary submission, 32 ms for sixteen slot exchanges, and 2 ms for a six-byte Write_block RF transmission exceed the corresponding SRI/CR14 frame-duration budgets at the fixed 500 µs watchdog. They are engineering allowances, not extra datasheet programming times. Valid answer reads confirm completion and replace an outstanding exchange guard with the 200 µs inter-request guard.
- After any Write_block submission attempt, including a failed ioctl, RF is held for 2 ms plus the configured programming time **starting after the ioctl returns**. Seven ms is the maximum SRI OTP/EEPROM/counter programming specification used here; a caller may configure a longer bound. The SRI specs label some electrical values estimated/target values; actual hardware qualification is required. No write is replayed, and all completed readbacks plus the currently uncertain address are reported. OTP/counter/lock semantics belong to the caller; observed data is returned rather than pretending all Write_block data has plain EEPROM semantics.
- Cleanup is explicit, waits for outstanding guards even after deadline expiration, writes RF off once, verifies register readback, and fences reuse after unconfirmed cleanup. Deadlines cannot interrupt Linux ioctl calls. The library does not implement kernel device nodes, probe/remove hooks, character stream state, module lifetime, userspace emulation of `/dev/rfid0`, or application event/NDEF policy.

Validation evidence is scripted transport/clock simulation and local compilation/testing. Physical RF behavior, error codes from a particular adapter, field shutdown, tag programming/restoration and antenna collision performance require separate device qualification. The repository does not claim hardware certification or that compile-only ARM checks execute on those machines.

Physical adapter observation on 2026-10-05: Raspberry Pi Zero 2 W, Linux aarch64, `bcm2835 (i2c@7e804000)`, `/dev/i2c-1` address `0x50`. A frame read immediately after INITIATE returned Linux `EIO`; the same read after a 4 ms RF guard succeeded. Only RF answer polling treats this as potentially busy. Invalid-register probing still required an actual `EREMOTEIO`/`ENXIO` NACK; configuration reads and all writes do not retry `EIO`. This observation does not prove tag programming or RF timing on other boards.
